# 行为验收用例

维护 Skill 时为所改分支选择这些用例。在隔离项目中提供原始输入、应用本 Skill、观察实际修改或报告；不要把本表作为评估代理的标准答案。状态与执行证据统一记录在 [validation.md](validation.md)，本表本身只表示已编写用例。

| ID | 输入 | 预期行为 | 失败条件 |
| --- | --- | --- | --- |
| C01 | 明确采用标准 COLA / Java 21 / Boot 3，要求增加业务写入与查询 | 先确定用例、层和职责；写入经领域/Gateway，纯查询可读 Infra；补适当测试 | Controller 访问 Mapper、盲目套相同调用层或扩大迁移 |
| C02 | 要增加对外输入、持久化快照、业务状态转换和转换器 | 分别给出名称、模块、包、依赖和调用方，关键依据可追溯 | 只讲抽象分层；把 DO 放进 Client；Domain 依赖 Infra |
| C03 | Controller 直接注入 Mapper 并计算业务价格 | 报出入口越过 App、业务规则位置错误，提出范围内修复 | 仅批评命名/长度，或认为传递依赖可见即允许 |
| C04 | 类级 `/api/v1/sales/orders` + 方法级 `/getOrder`；任务授权改造该接口 | 完整业务路径移到方法，保留 /api/v1，选择资源化形式与真实状态 | 丢失前缀、继续隐含父类前缀、所有结果 200 |
| C05 | DTO 使用 Lombok，要求 MapStruct 映射到受控领域对象 | 配置 processor/binding 并编译，映射经过领域构造，不生成全 setter 破坏约束 | 仅列依赖未验证；在 converter 加业务定价；Domain @Data 导致任意改状态 |
| C06 | 普通非 COLA Java 项目，要求修正字符串格式化函数 | 识别不适用，继续原局部任务；不引入 COLA 模块或迁移 | 仅因 Java/Spring 就主动重构成 COLA |
| C07 | 格式化后 490 行业务执行器，新职责使文件将达 530 行 | 开发前识别，按业务能力拆分，验证行为和一致性 | 追加到超限、压缩排版、搬入 Utils、机械拆段 |
| C08 | 超过 500 行的单一配置声明类，没有业务行为 | 按内容判断可读性与例外，记录路径、行数、依据 | 只按行数机械拆分；只看类名不读职责 |
| C09 | 超过 500 行的 Entity 含复杂状态和业务规则 | 视作业务逻辑类；提出保持领域封装的拆分 | 把 Entity 后缀当作数据类豁免 |
| C10 | 存量 800 行业务类局部缺陷，用户只授权小修 | 在范围内修复，必要时局部调整，准确记录遗留超限 | 全项目重构；把未处理问题写成已合规 |
| C11 | 不足 500 行的类混杂定价、导出、发信和 SQL | 识别职责与分层问题，即使行数合规 | 只按阈值给“通过” |
| C12 | 明确采用 COLA light 的单模块项目，要求业务变更 | 说明本 Skill 未覆盖，沿目标约定处理可完成部分 | 强制迁移标准多模块或混用依赖规则 |
| C13 | 订单取消首次、相同内容重试、不同原因重试 | 201/200/409；原时间不变，冲突不写状态，Location 可查询 | 新建多份记录、重试改时间、冲突仍 HTTP 200 |
| C14 | 使用 COLA 包装的接口返回 204；框架抛 400/405/415/406；整数数量收到小数输入 | 204 无体，框架状态/Allow 保留；不支持的响应类型在写入前拒绝；小数数量返回 400 | 204 包装 JSON、吞状态码、泄漏内部异常、406 后仍写入、数量被静默截断 |
| C15 | 行数工具输入 500/501、换行差异、生成文件、内部类与混合 Git 变更，含暂存/未暂存类型变更 | 物理计数准确，候选和排除依据清楚，仅统计实际范围 | 文件名自动豁免、候选直接判全仓违规、类型变更漏检、错误输入假成功 |

代表性的自动化边界：领域对象公共行为、OrderServiceI、实际 HTTP、MapStruct 转换接口，以及统计工具 CLI。编译/单元/集成测试验证示例行为，不自动证明 Codex 在所有任务中都能遵守 Skill；独立代理验收另记实际输入、输出与范围。
