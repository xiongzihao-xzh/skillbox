# 完成前审查清单

先记录任务授权范围、变更文件集、基线提交及实际执行的检查；用户只授权局部时，对范围外问题给位置与建议。

| 检查面 | 必须回答的问题 | 证据 |
| --- | --- | --- |
| 适用范围 | 是否明确采用受支持的 COLA 标准方案？项目规则冲突如何处理？ | AGENTS/架构说明/POM/用户指令 |
| 来源分类 | 是否把示例写法或项目偏好误称官方强制？是否混用版本/变体？ | sources.md 中相应固定来源 |
| 依赖 | 与所选 POM 图一致？Controller 是否绕过 API？Domain 是否依赖 Infra/HTTP？ | 变更 POM、import、实际调用 |
| 对象与转换 | Cmd/Qry/DTO/Domain/DO 是否职责明确？转换所在层允许依赖两端？ | 类定义与转换入口 |
| 业务与事务 | 不变量是否能被非 HTTP 调用绕过？原子性、异常传播和外部副作用如何保证？ | 行为测试与实际存储保证；未验证项明确 |
| 路由 | 方法级是否包含完整业务路径及既有前缀？父类/接口是否藏有前缀？ | 所有本次相关映射及继承链 |
| HTTP | 方法语义、业务资源、参数、状态、错误码、缓存是否匹配？ | HTTP/序列化测试，不仅 Java 返回值 |
| Java / Boot | JDK 21、Boot 3.x 与依赖/processor 是否兼容？ | java/mvn 版本、有效 POM、实际编译 |
| 工具库 | 是否保留领域封装？MapStruct 是否真实生成、遗漏字段是否暴露？ | 编译产物和有意义的映射测试 |
| 类规模 | 正常格式化后统计了哪些文件？所有候选的职责与处理是什么？ | [规模记录](code-quality.md#完成记录) |
| 设计质量 | 未超过 500 行是否仍职责混杂、复杂或难测？拆分是否改善内聚性？ | 业务协作和测试观察 |
| 结果准确性 | 已编写、静态检查、实际运行、验证通过是否区分？ | 实际命令、退出状态、测试报告 |

规模检查在开发前预判、开发中控制、完成后复核。新增业务类满足 500 行上限，声明/数据例外要有依据，存量未处理问题不写成已合规。仅检查变更范围不宣称全仓合规。

审查输出按“发现 → 文件位置 → 行为或边界影响 → 建议及范围”组织。没有发现也说明检查范围和未验证部分；生成文件排除需可追溯依据。
