# 类规模与职责控制（项目约定）

## 开发前、中、后

开发前检查将被扩展的类：它负责哪个用例/业务能力，现有职责是否一致，格式化后的规模是否接近上限。开发中保持领域规则、用例编排和事务边界可追踪；新增职责应有明确归属。完成后对本次新增/修改的 Java 文件重新统计并判断实际职责。

**手写业务逻辑类**承载规则、流程编排或用例执行，一个源文件最多 500 行。统计包括 package、import、注解、空行、注释、内部类、嵌套类和其他辅助类型；按正常项目格式化后的物理总行数计算。保持排版和必要注释，避免用压缩语句掩盖复杂度。

| 观察 | 判断与处理 |
| --- | --- |
| 490 行的业务执行器，新增职责会超过 500 | 在当前用例范围内先按独立职责拆分，保持行为和事务一致 |
| 650 行单一字段/注解声明的配置类 | 核对确实主要由声明构成、可读可维护后，记录例外依据；不按数字机械拆分 |
| 650 行 Entity 包含审批和状态转换 | 属于业务逻辑类，名称不提供豁免；按领域能力拆分 |
| 250 行 Service 同时定价、发邮件、拼 SQL | 同时报告职责与分层问题，行数合规不能代替设计判断 |
| 修复存量 800 行业务类的局部缺陷 | 在授权范围内修复，必要时局部拆分；整体重构超范围则记录遗留问题，不能宣称合规 |
| 构建生成的 MapperImpl | 核验 generator 与构建目录，作为非手工维护文件排除并记录依据 |

声明型/数据型例外取决于主要职责和超长原因，不是注解或后缀白名单。Configuration、DTO、DO、Entity、Helper、Utils 内包含业务规则时都需按业务逻辑判断；位于错误层时同时纠正落位。

拆分按业务能力、用例或协作边界，避免按固定行数切片、无意义继承和把逻辑塞进通用工具类。500 是上限而非目标。新增业务类满足上限；修改不能让原本合规的业务类超限；存量超限的暂时保留不等于获得例外。

## 统计工具

`scripts/java_line_counts.py` 仅依赖 Python 3 标准库。下文 `<skill-dir>` 是安装后本 Skill 的目录，`--root` 是目标项目路径；不依赖研究时的 COLA 源仓库。

```bash
# 默认：Git 仓库根下，暂存 + 未暂存 + 未跟踪的 Java 变更，含类型变更，忽略删除项
python3 <skill-dir>/scripts/java_line_counts.py --root <repository-root>

# 显式选择（相对于 root）；适合非 Git 项目和本次已知文件集合
python3 <skill-dir>/scripts/java_line_counts.py --root <project> src/main/java/example/Order.java

# 显式全量；只有实际执行全量且完成职责判断才能报告全仓结果
python3 <skill-dir>/scripts/java_line_counts.py --root <project> --all

# 先核验 pom.xml 与构建日志，再提供生成目录依据
python3 <skill-dir>/scripts/java_line_counts.py --root <project> --all \
  --generated-root 'orders-app/target/generated-sources=MapStruct, maven-compiler-plugin in pom.xml'
```

`--generated-root` 可重复，形式是 `PATH=BASIS`。工具记录调用方提供的依据，并不自动证明这个目录没有手写文件；审查者须先核验生成配置。任意文件名、`@Generated` 注释或人工声称不能替代来源依据。默认不按类名或目录名偷偷豁免；全量运行需显式列出已核验的生成目录。

JSON 输出包含 `scope`、`limit`、`files`（路径/物理行数/`over_limit`）与 `excluded`（路径/依据）。退出码 0 表示统计成功，即使存在候选；退出码 2 表示参数、文件、编码或仓库范围错误。候选不等于违规，工具不会输出“全仓架构通过”。默认变更模式合并暂存区相对 HEAD、工作区相对暂存区的变更及未跟踪文件，读取其当前工作区内容；两次修改相互抵消时仍纳入范围。提交之间的审查应显式传入约定范围的文件。

## 完成记录

对每个超限候选给出以下信息（包括本次暂时保留项）：

| 文件 | 物理行数 | 实际职责与依据 | 处理结果 |
| --- | --- | --- | --- |
| 目标项目实际路径 | 实际统计值 | 用例执行/领域行为/单一配置声明等 | 已合理拆分；声明/数据例外及依据；存量未处理及原因 |

无超限候选时仍检查职责和复杂度。拆分完成后重新格式化、统计并运行相关行为测试；所有范围外问题给出位置、影响和后续建议。
