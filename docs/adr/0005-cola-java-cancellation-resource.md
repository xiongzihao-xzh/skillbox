# 用单例取消资源表达订单取消

销售订单示例采用 `PUT /sales/orders/{orderId}/cancellation` 表达取消，每个订单至多拥有一份包含原因和时间的取消记录。该记录具有独立的业务含义和固定 URI，既表达订单状态变化，又让请求重试复用首次结果；示例选择这一契约，而非只用 PATCH 改写订单状态。

| 场景 | HTTP 结果 | 业务结果 |
| --- | --- | --- |
| 首次成功取消 | 201 | 创建取消记录，订单变为 CANCELLED |
| 相同取消内容重试 | 200 | 返回原记录，保留首次时间，不重复执行取消 |
| 请求更改已记录的取消原因 | 409 | 保留原记录与订单状态，返回明确的业务错误 |

相同内容指相同业务输入，不要求 JSON 文本逐字相同；首次取消时间由服务端确定，不由重试更新。实现须保证状态变更与取消记录在并发重试下仍一致，并以测试核验；有响应体时遵循 [HTTP 响应契约](0004-cola-java-http-response-contract.md)。

这是示例的项目契约：`cancellation` 表示单例子资源，资源集合仍使用复数名称。[RFC 9110 §9.3.4](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.4) 提供 PUT 的资源状态和幂等语义，并未规定订单取消必须采用这个 URI 或模型。
